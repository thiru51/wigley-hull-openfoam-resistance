# Method

## What is being computed

The resistance of a towed Wigley hull at steady forward speed, in calm water,
at model scale — and specifically the split between the two things that resist
a ship:

* **friction**, from the water shearing along the hull;
* **pressure resistance**, which at these speeds is mostly the energy carried
  away by the wave pattern the hull leaves behind.

The wave part is the interesting one, because it can be predicted
independently: Michell's 1898 thin-ship integral gives a closed-form wave
resistance for a hull whose beam is small compared with its length, which the
Wigley form is. That gives the CFD something to be judged against that was
not fitted to it.

## Geometry

The Wigley parabolic hull,

```
y(x, z) = (B/2) (1 − (2x/L)²) (1 − (z/T)²)
```

at `L = 3.0 m`, `B = 0.3 m`, `T = 0.1875 m` — the standard 1 : 0.1 : 0.0625
proportions, at a typical towing-tank model size. The surface mesh is written
by the companion project [hullform](../hullform), which also produces the
Rhino model and the hydrostatics of the same hull, so the CFD and the naval
architecture start from one definition of the geometry rather than two.

The hull is extruded vertically above the design waterline (the Wigley form is
defined only to the DWL) and closed with a centreplane and a deck, giving a
watertight surface: `snappyHexMesh` decides inside from outside by ray
casting, and a leaky surface produces a quietly wrong mesh.

## Domain and mesh

Half the ship is modelled, with a symmetry plane on the centreline.

| Boundary | Position | Condition |
|---|---|---|
| inlet | 1.25 L ahead of midships | fixed velocity, variable-height flow rate on α |
| outlet | 2.0 L aft | outlet phase mean velocity, holding the still-water level |
| side | 1.1 L abeam | slip |
| bottom | 0.7 L below | fixed velocity |
| atmosphere | 0.35 L above | total pressure, inlet-outlet velocity |
| hull | — | no slip, wall functions |

Meshing runs in three stages:

1. `blockMesh` lays a uniform background grid.
2. `refineMesh` splits the free-surface band **in z only**, two or three
   times. The waves are long and thin: refining isotropically would spend
   cells on a direction where nothing happens.
3. `snappyHexMesh` refines towards the hull surface and snaps to it, with an
   extra refinement region around the ship.

The medium mesh is about 268,000 cells; coarse and fine variants exist for the
mesh study and are generated by the same script with one argument changed.

## Solver

`interFoam` — a volume-of-fluid solver, with the air and the water as one
field and the interface captured by the volume fraction α.

Steady state is reached by **local time stepping** rather than by marching in
real time: each cell advances at its own stable rate, so the solution relaxes
towards the steady wave field in far fewer iterations than a transient run
would need. This is the approach OpenFOAM's own DTC hull tutorial uses for
ship resistance.

Turbulence is k-ω SST with wall functions. There are no prism layers on the
hull, which is a deliberate limitation, stated in the results: y⁺ is far above
the log-layer range, so the **friction** from the CFD is not trustworthy and
is reported alongside the ITTC-1957 correlation line rather than instead of
it. The pressure force, which is what the wave-resistance comparison rests on,
is not sensitive to the near-wall mesh in the same way.

## What comes out

The `forces` function object integrates pressure and viscous traction over the
hull every ten iterations. The last 20 % of the run is averaged — the tail
scatter is reported in the results table, so the reader can see how settled
each case is — and turned into coefficients with the wetted surface of the
half hull:

```
Ct = R_total / (½ ρ S U²)      Cp = R_pressure / (½ ρ S U²)      Cf = R_viscous / (½ ρ S U²)
```

`Cp` is compared with Michell's `Cw`; `Cf` with the ITTC-1957 line; and
`Cp + Cf_ITTC` gives a corrected total resistance, which is the practical way
of using a computation whose friction is under-resolved.

## Reproducing it

```bash
python tools/gen_case.py --fn 0.316 --level medium --out cases/fn0316 --iters 1200
bash tools/run_case.sh cases/fn0316 10
python tools/postprocess.py
python tools/plots.py
```

`tools/sweep.sh` runs the whole Froude-number sweep and the mesh study two
cases at a time.

## Known limitations

1. **No prism layers**, so wall-resolved friction is not available; see above.
2. **The hull is fixed** — no sinkage and trim. At Froude numbers up to about
   0.4 that matters more for the total than for the wave pattern, but it is a
   real difference from a towing-tank test, where the model is free to heave
   and pitch.
3. **No wave damping zone.** The domain is sized so reflections do not reach
   the hull within the run, rather than being absorbed.
4. **Michell's theory is itself approximate**: it assumes a thin hull and
   linearised free-surface conditions, so it is a reference, not a truth.
